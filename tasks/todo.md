# 作業計画: 縦スクロール弾幕シューティング（仮題）

## 2026-11-16: 開発計画

### 目的

90 年代アーケードの縦シューを思わせるドット絵の弾幕シューティングを作り、iPhone の Safari で遊べるようにする。目標の体験は二つ。

1. 画面を埋める弾幕を、小さな当たり判定ですり抜ける緊張感
2. 敵をまとめて倒し、コンボがつながり、ボス撃破で弾が一斉に消える爽快感

### 作らないもの（著作権の線引き）

『怒首領蜂』は**ジャンルと手触りの参考**にとどめる。名前・キャラクター・機体デザイン・音楽・ステージ構成・画面レイアウトは真似せず、すべてオリジナルにする。弾幕・コンボ・弾消しのようなジャンル共通の仕組みは使ってよい。

### 『桜井政博のゲーム作るには』から取り入れる考え方

あーしの記憶をもとにまとめた。動画のタイトルや細かい言い回しはまだ確かめていない。

| 考え方 | このゲームでやること |
|---|---|
| まず遊びの核を作り、そこを気持ちよくする | M1 では「動かす・撃つ・壊す」だけを作り、iPhone で触って気持ちいいかを確かめてから先へ進む |
| 手触り（ヒットストップ、揺れ、光） | 被弾中の敵を白く光らせる、大きな撃破でごく短いヒットストップと画面の揺れ、破片、効果音 |
| リスクとリターン | 敵に近づいて倒すほど得点が増える。コンボを切らさないには前に出る必要がある |
| 緊張と緩和 | 弾幕のピーク → 撃破 → 弾消し → 短い静けさ、の波をステージの時間割として設計する |
| 遊ぶ人の目線 | 当たり判定は見た目よりずっと小さい点にして表示もする。理不尽な被弾をなくし、初心者向けに被弾時の自動ボムを選べるようにする |

### 技術方針（Kart Rush の経験を引き継ぐ）

- **HTML 1 ファイル + Canvas 2D、ビルドなし**。3D が要らないので Three.js も使わない。外部依存はゼロにする。
- **配布は GitHub Pages**（kakankan677 アカウントに新しい公開リポジトリ）。Artifact は iframe の制約があるため、補助的な扱いにとどめる。
- **ドット絵の見せ方**: 内部解像度は 240×320 前後の小さなキャンバスに描き、整数倍に拡大してぼかしを切る（`imageSmoothingEnabled = false`）。縦長画面の余白は HUD に使う。
- **ドット絵の作り方**: 文字列で書いた絵とパレットから、起動時にスプライトを生成する。画像ファイルなしで、全部オリジナル。
- **iPhone の操作**: 指を置いた位置からのずれで自機を動かす（指で自機が隠れない）。ショットは触っている間ずっと撃つ。ボムはボタン。DoDonPachi 系の「ショット／レーザーの撃ち分け」をスマホでどう表現するかは M1 で 2〜3 案を試して決める。
- **処理落ち対策**: 弾・敵・破片はあらかじめ確保した配列を使い回す（オブジェクトプール）。ゲームの更新は 60Hz 固定にし、120Hz 画面でも速さが変わらないようにする。目安は弾 1000 発で 60fps。
- **音**: WebAudio で効果音を合成する。画面が隠れたら止める（kart-race の教訓）。

### 検証方法

- Mac の内蔵ブラウザ: キーボード操作、デバッグ用の自動操作と無敵モードで通しプレイ、コンソールエラーがないこと。
- iPhone 実機（がっちゃん）: 操作感、fps、音、ホーム画面追加。実機で確かめるまでは「未確認」と書く。

### リスク

- iPhone で弾が多いと重くなるかもしれない → M2 で早めに測る。
- 指の操作は試さないと良し悪しが分からない → M1 で複数案を比べる。
- 弾が背景に埋もれて見えない → 背景は暗く低コントラスト、敵弾は明るい色に縁取りを付け、画面で一番目立つものにする。
